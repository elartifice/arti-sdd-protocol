# Validation and release boundaries

The release gate combines deterministic regression tests, native CLI qualification, and verification of the exact exported artifacts. The versioned native results and package digest are in [QUALIFICATION.md](QUALIFICATION.md) and [qualification.json](qualification.json).

| Area | Observable acceptance |
|---|---|
| Charter and setup | Explicit false and undecided review policy survive handoff; new/unborn and existing repositories preserve owner content; repeat apply is stable. |
| Setup preservation and recovery | A real killed installer restores original bytes only in its originating worktree; stale concurrent previews refuse; disabled owned adapters retire without removing owner agents. |
| Scope and ownership | Literal paths, moves, dangling links, worktrees and header IDs are checked; two competing owners cannot claim one ticket; disjoint claims can proceed. |
| Coordination | Real separate clones compare-and-create a unique remote claim; interrupted acquisition preserves remote intent; approved integration contracts cannot be weakened by editing and reclaiming. |
| Completion | Required review belongs to this ticket and generation; an old merge cannot close reopened work; cleanup reserves completion before releasing claims and locks. |
| Native roles | Every enabled role is actually invoked; client model metadata, task behavior, retained assertions, shared knowledge and permission boundaries have separate checks. |
| Ordinary dispatch | Production helper emits supported native arguments, rejects stale bindings and correlates actual child model/effort evidence. Both native clients deny generic routes; desktop bindings have separate live task checks without a native-profile claim. |
| Shared discovery | Both clients discover the canonical protocol and five rituals; Claude links resolve to the shared files. Fresh-context handoffs read durable knowledge and existing approval. |
| Review | Both labs consume the supplied complete dossier in isolated processes; repeated security/quantity defects and clean controls test quality; incomplete, stale or unqualified evidence cannot pass. |
| Distribution | An allowlisted source tree and skill ZIP exclude private inputs and raw logs; actual extraction, installation and exported-source tests run locally. |

Run `npm test` and `npm run check` without models. `npm run test:live` explicitly uses existing CLI authentication and quota. `node dev/package.mjs --require-qualified` requires a fresh passing release report for the package being exported. The [hosted CI workflow](https://github.com/elartifice/arti-sdd-protocol/actions/workflows/check.yml) runs the deterministic macOS/Linux Node 22/24 matrix. Require a successful run on the exact release commit before creating a release; the workflow history is separate from native qualification.

The final v0.5.0 candidate passes 174 deterministic tests with no skips: source runs on Node.js 22.23.4 and 25.8.1, and the actual allowlisted source export on Node.js 24.22.3 with Claude, Codex and GitHub CLIs absent from PATH, as in hosted CI. The changed board and native-output proof fixtures also pass focused checks on Node.js 24.22.3. Archive checks verify its digest, CRCs, safe paths, MIT notice, identical extracted core hash, both-host installation, shared Claude links and idempotent reapplication. Native qualification is recorded separately; historical reports do not qualify changed code. Tests include actual process races, separate Git clones, worktrees, linked CLI execution and killed-installer recovery, rather than only rendered-configuration assertions.

Claude exposes requested effort settings without effective-effort telemetry. Codex native read-only roles inherit the parent's permissions and are qualified under a read-only parent. Use the isolated external reviewer from a writable coordinator. Hook guards do not enforce arbitrary shell writes; the candidate's approved scope and checks remain required at verification.

The named role profiles govern those invocations. The host's primary session model remains the user's choice, and the primary session coordinates delegation subject to the host's nesting limits. An existing coordinator-issued claim can be validated without writing protected runtime state; acquiring or releasing ownership remains a coordinator operation.

Remote claims protect ticket IDs across machines; local frozen territory checks do not replace coordinator-assigned disjoint work across different clones. Native integrations beyond the recorded macOS Claude Code/Codex versions remain unqualified. Desktop model routing is tested separately; desktop native profile selection and hook enforcement remain unsupported/unproven. The hosted Projects and native continuation adapters ship separately in the source distribution. Recording, deployment and backup implementations are outside this core.

Raw transcripts, synthetic session IDs and temporary workspace paths remain private. Persisted native test sessions remain for the owner to manage. The proposed public source is `dist/public-repository/`; a future authorized update must preserve the existing public repository history and exclude this private implementation history. No build or validation command uploads a release.

The routing-cost replay uses the same recorded requests and separately checks replacement-model context tiers, unknown-role handling, coordinator-policy effects and independently calculated totals. It does not assert measured token reduction or equal quality under replacement models. The hosted board is an optional implemented adapter with a separate live qualification requirement; an illustrative local board is not a bundled application. Update notification and downstream adoption remain owner controlled.


The reliability matrix adds authoritative Issue contracts and stale-approval rejection; lost-response draft reconciliation; persistent Projects readback and multi-repository identity; ordered integration/stable validation and applicable human acceptance; canonical baseline/delta interaction review; repeated-correction diagnosis; identity-bound wait cancellation, expiry and deduplication; actual native timer-to-work continuation followed by verified fixture landing; and metadata-only claim/completion title persistence. No downstream protocol or global service is activated by these fixtures. Live GitHub Projects access is separately required and cannot be replaced by mocked API results.

A monitor is an explicitly running process with a heartbeat and bounded expiry. A registered wait alone is not automatic continuation. A failed or stopped process cannot wake a session; uncertain delivery requires inspection before retry. Codex custom role prose is not a per-role OS sandbox. Claude effective effort remains requested, not independently observable. CLI compaction and task retention are tested separately from Desktop UI behavior. Desktop wake/stop integration and a coordinator in a different directory from the resumed candidate remain unqualified.

The frozen native profile passed on 2026-11-17: 12 role tasks, 14 opposite-lab defect/control trials, two real production review dispatches, two corrective reviews with cross-direction/intermediate findings, both native continuation/naming routes, both fresh-session drafts and concurrent cross-host ticket work. Live authoritative Issue closeout and persisted CRLF readback also passed, as did native compaction on both hosts. Hosted Projects passed its separate real API and both-host native lifecycle qualification on 2026-11-19 against the unchanged core and client versions. Both hosts executed the exact helper, then real fixture landing and worktree cleanup preserved the hosted Project. The selected live portfolio covered one upstream repository; multiple-repository identity and pagination are fixture-tested, not claimed as a live portfolio test. No downstream installation or global service was changed.
