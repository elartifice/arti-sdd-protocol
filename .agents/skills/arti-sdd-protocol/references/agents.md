# Qualifying roles and review

Use named coordinator, scout, implementer, reviewer and escalation roles. Define the role once in `.agents/roles`; bind models separately for each host in `.agents/team.json`. The main coordinator owns decisions; scouts gather read-only evidence; implementers own exclusive files; reviewers return findings; escalation takes a compact failure dossier after repeated failure. Ordinary work does not need every role.

Model IDs, effort, expected effective IDs and CLI route are explicit. Resolve them from actual account access, then qualify them; do not equate marketing tiers or effort labels across labs. An OK response proves access only. Do not use a CLI default when a mapping is missing, malformed or belongs to the other lab. Changing a binding or client version invalidates its qualification.

For each enabled native role, prove discovery and actual invocation, model/effort evidence, relevant shared knowledge, task quality and scope behavior. Scout: locate seeded facts without invented symbols or edits. Implementer: repair a bounded behavior with retained assertions. Reviewer: find both seeded defects, accept a clean control and mutate no product files. Coordinator: choose ready work and reject incomplete evidence. Escalation: solve a bounded dossier without repeating rejected approaches or widening scope.

Cross-lab review policy is a setup decision without a preselected answer. Required and selected risk-scoped reviews block when unavailable; opportunistic and disabled modes report their actual state. An owner exception is tied to a particular revision and cannot masquerade as a successful review.

Run the other lab through `scripts/review.mjs`. The wrapper owns receipts; the child receives rules, shared knowledge, the linked specification, ticket and complete diff without repository or connector tools. Both labs run outside the candidate tree. Claude safe mode excludes candidate/user customizations while retaining native login; Codex excludes user configuration, apps and plugins. Capture a valid final response, actual client-reported model evidence, exact base/head/snapshot digest and explicit complete coverage. Require the expected lab/model and qualified role-source fingerprint. Missing base, dirty candidate, truncation, authentication failure, timeout, error, startup chatter and malformed findings fail a required review. Accepted findings must be resolved or explicitly triaged according to project policy. Any candidate change makes prior evidence stale.

Live qualification uses identical fixtures on both labs and repeated reviewer trials in both directions, plus clean controls. Keep raw logs private and publish only sanitised summaries bound to the tested package digest and client versions. Clearly distinguish configured, access-probed, behavior-qualified and live-enforced capabilities. Native Codex role restrictions remain bounded by the parent's permissions; do not claim a per-role sandbox.

Codex reports resolved reasoning effort in native activity/client metadata. Claude exposes the requested CLI/role setting but no effective-effort telemetry. Record `effort_verified: false` for Claude and state that limit; behavior tests qualify the requested configuration, not an independently observed internal effort level. Never describe requested settings as measured vendor equivalence.

Run the public source repository's `node dev/qualify.mjs --target <project>` to test that project's exact five-role mapping and shared role instructions in disposable fixtures. With no target it tests access-probed release candidates. This uses existing CLI logins and quota, writes private logs, and leaves persisted Codex test sessions for the owner to manage. Import a trusted passing report with `node <skill>/scripts/team.mjs --repo <project> --evidence <report.json>`; `--require-live` then checks freshness. Import refuses changed sources, package, model, effort or CLI versions and missing repeated defect/clean trials. Receipts are local evidence, not signed third-party attestations. Requalify after credential/access changes.

Claude's edit permission does not grant shell tests: authorise the actual project's test commands in the parent, retaining denial behavior. A Codex author invoking the external review wrapper needs network access and write access to the private Git-common runtime directory for receipts; the child reviewer stays read-only. Use an explicit scoped approval/configuration for that command, never silently relax the parent sandbox. Missing permission is a blocked review.
