# Qualifying roles and review

Use named coordinator, scout, implementer, reviewer and escalation roles. Define the role once in `.agents/roles`; bind models separately for each host in `.agents/team.json`. The main coordinator owns decisions; scouts gather read-only evidence; implementers own exclusive files; reviewers return findings; escalation takes a compact failure dossier after repeated failure. Ordinary work does not need every role.

Model IDs, effort, expected effective IDs and CLI route are explicit. Resolve them from actual account access, then qualify them; do not equate marketing tiers or effort labels across labs. An OK response proves access only. Do not use a CLI default when a mapping is missing, malformed or belongs to the other lab. Changing a binding or client version invalidates its qualification.

Before ordinary delegation, prepare a request with `node <skill>/scripts/dispatch.mjs plan --repo <project> --host claude|codex --surface claude-agent|codex-agent|codex-collaboration --role <role> --task-file <private-dossier>`, adding `--assigned <relative-file>` for each writable file. Save its JSON privately and use the emitted tool and arguments exactly. Claude Agent and Codex CLI select the native `arti_<role>` profile; a built-in generic worker does not load it. Codex desktop's `collaboration.spawn_agent` has no native profile selector: send both configured `model` and `reasoning_effort`, use `fork_turns: none`, and include the shared role source plus compact task/approval/knowledge dossier. Do not override a model on a full-history fork. If a host cannot honour the binding, use a qualified CLI route or report BLOCKED.

Before accepting the result, run `dispatch.mjs verify --plan <private-plan.json> --evidence <native-evidence.json>`. Supply Claude stream-json events as a trusted local log, or Codex `{"threadId":"<native-child-id>"}`. The checker fetches Codex native state itself and reads its stored session path; supplied thread/rollout JSON is rejected. Codex seals delegated message text at rest, so correlation checks the unique native child path, parent ID and the dispatch ID echoed in its final report; model and effort come from native metadata, never its self-report. The evidence must match the request, current sources, effective model and observable effort. Desktop results retain the explicit label that native profile identity and per-role permission isolation are unsupported by that tool. Supported native PreToolUse hooks reject generic or conflicting named-role dispatch; other surfaces require the explicit plan/evidence check.

For each enabled native role, prove discovery and actual invocation, model/effort evidence, relevant shared knowledge, task quality and scope behavior. Scout: locate seeded facts without invented symbols or edits. Implementer: repair a bounded behavior with retained assertions. Reviewer: find both seeded defects, accept a clean control and mutate no product files. Coordinator: choose ready work and reject incomplete evidence. Escalation: solve a bounded dossier without repeating rejected approaches or widening scope.

Cross-lab review policy is a setup decision without a preselected answer. Required and selected risk-scoped reviews block when unavailable; opportunistic and disabled modes report their actual state. An owner exception is tied to a particular revision and cannot masquerade as a successful review.

Run the other lab through `scripts/review.mjs`. The wrapper owns receipts; the child receives rules, shared knowledge, the linked specification, ticket and complete diff without repository or connector tools. Both labs run outside the candidate tree. Claude safe mode excludes candidate/user customizations while retaining native login; Codex excludes user configuration, apps and plugins. Capture a valid final response, actual client-reported model evidence, exact base/head/snapshot digest and explicit complete coverage. Require the expected lab/model and qualified role-source fingerprint. Missing base, dirty candidate, truncation, authentication failure, timeout, error, startup chatter and malformed findings fail a required review. Accepted findings must be resolved or explicitly triaged according to project policy. Any candidate change makes prior evidence stale.

Live qualification uses identical fixtures on both labs and repeated reviewer trials in both directions, plus clean controls. Keep raw logs private and publish only sanitised summaries bound to the tested package digest and client versions. Clearly distinguish configured, access-probed, behavior-qualified and live-enforced capabilities. Native Codex role restrictions remain bounded by the parent's permissions; do not claim a per-role sandbox.

Codex reports resolved reasoning effort in native activity/client metadata. Claude exposes the requested CLI/role setting but no effective-effort telemetry. Record `effort_verified: false` for Claude and state that limit; behavior tests qualify the requested configuration, not an independently observed internal effort level. Never describe requested settings as measured vendor equivalence.

Run the public source repository's `node dev/qualify.mjs --target <project>` to test that project's exact enabled-role mapping and shared role instructions in disposable fixtures. With no target it tests access-probed release candidates. This uses existing CLI logins and quota, writes private logs, and leaves persisted Codex test sessions for the owner to manage. Import a trusted passing report with `node <skill>/scripts/team.mjs --repo <project> --evidence <report.json>`; `--require-live` then checks freshness. Import refuses changed sources, package, model, effort or CLI versions and missing repeated defect/clean trials. Receipts are local evidence, not signed third-party attestations. Requalify after credential/access changes.

Claude's edit permission does not grant shell tests: authorise the actual project's test commands in the parent, retaining denial behavior. A Codex author invoking the external review wrapper needs network access and write access to the private Git-common runtime directory for receipts; the child reviewer stays read-only. Use an explicit scoped approval/configuration for that command, never silently relax the parent sandbox. Missing permission is a blocked review.

For the optional recent-evidence researcher, read [research.md](research.md). It requires the pinned 90-day multi-source collector, a supplied dossier instead of local reads, explicit per-host bindings and separate native qualification.

Final production review requires the current automated acceptance receipt first; a ticket's optional `validation` object selects ordered `reproduce`, `focused`, `integration` and `stable` command lists plus explicit `human_required`. Focused checks serve iteration; the stable gate runs on the coherent final candidate. If human acceptance is selected, record only actual owner acceptance using `scripts/acceptance.mjs human` with its source and observed evidence. Never invent that receipt. Changed behavior invalidates applicable acceptance; this conservative core binds acceptance to the exact revision. `review.mjs --stage early-safety` permits targeted review before a consequential action but cannot pass the final landing gate.

For corrective review, pass the previous canonical receipt with `--previous <private-receipt.json>`. The wrapper verifies unchanged rules, knowledge, specification, contract, package, role/binding, CLI and base; strict ancestry; canonical complete baseline coverage; and the exact delta. The reviewer receives previous findings and current complete changed-file sources and must explicitly attest interaction coverage. Missing or oversized context requires a full review/split, never a filename-union waiver. `reuseReview` accepts an unchanged complete passing canonical receipt without another model call. After two failed corrective cycles, provide `--diagnosis <private-json>` containing a concrete `cause` and `revised_approach`, even when choosing a fresh full review. Unresolved required findings remain blocking. Receipts state the actual head reviewed and purpose; qualification and early safety evidence cannot become production final review.


Native ticket naming is owned by the agent at claim and verified closeout. Use a supported native title tool first, then `scripts/naming.mjs --repo <repo> --ticket <ID> --host claude|codex --native-session <bound-id> --event claim|land`. Codex uses official app-server metadata operations and fresh-connection readback. Claude's optional metadata fallback requires an explicitly installed official `@anthropic-ai/claude-agent-sdk` (qualified version 0.3.325); pass its absolute `sdk.mjs` path through `--sdk-module`. The helper calls only `getSessionInfo`, `getSessionMessages` and `renameSession`, scoped to this repository, and verifies unchanged conversation messages. It starts/resumes no model turn and never edits host storage directly. Do not install the dependency merely by invoking the core skill. Missing SDK/native capabilities produce an honest failure receipt without a manual-renaming chore. See the [official SDK session APIs](https://code.claude.com/docs/en/agent-sdk/typescript#renamesession).

Review context includes existing source files explicitly referenced by the ticket's check commands. Add a bounded `review_context` path list for other unchanged tests or interacting source the reviewer needs; these inputs are hashed and changes invalidate composition. The reviewer receives actual current check evidence when available. Missing changed test lines do not establish that existing regression tests are absent. Insufficient context must remain incomplete rather than guessed.

Rules, knowledge, specification, team bindings and the reviewer role come from the approved claim/integration baseline. Candidate changes are proposed diff data and cannot redefine their own review standard; owner reconciliation precedes changed reviewer bindings/role qualification. Existing tests and selected `review_context` come from regular blobs in the exact candidate commit. Links, ignored/uncommitted files, Git internals and sensitive paths are refused. Include relevant linked knowledge topics explicitly; an index link alone is not the topic's content. External/untracked check tools are not read as project source. Executable checks do not load this model context.

An explicit validation plan supplies the executed commands; legacy `checks` is the fallback. Receipts fingerprint the actual ordered commands, and their referenced source files enter review context. Every review attempt has its own canonical receipt. Incomplete coverage preserves valid reported defects. Known blockers from both labs survive retries, amended/rebased history and older corrective baselines; a complete review must explicitly recheck them. Supplemental source that cannot safely fit is labelled unavailable, never treated as proof of resolution. A canonical complete pass can supersede the exact findings it checked. Chains stop before exceeding their verifiable depth and offer a fresh full review. Repeated full reviews cannot evade the corrective-diagnosis requirement.
