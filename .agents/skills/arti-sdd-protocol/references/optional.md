# Optional modules and evidence

The core ships Markdown planning and deterministic helpers. It does not ship a graphical board, browser recorder, deployment adapter, issue mirror or untracked backup scheduler. Selecting an unavailable module must produce an explicit unsupported result; no stub may count as installed or verified.

If adding a board, serve only its intended read-only files on loopback. Never serve the whole private state directory. Show missing/stale data honestly, label demo data, copy the selected host's command and verify that the chosen surface actually opens. Avoid speculative Mod APIs and unverified deep links.

Recorded QA is ticket-driven. Honour selected golden or composed input policy. Use the intended consented local browser/profile and existing target; do not bypass connection consent or switch to another user's browser. Require first-frame readiness and reject zero-frame recordings. Preserve raw wait time and label any acceleration; native capture and historical recordings cannot certify a fresh browser test. Incomplete diagnostics have unknown counts rather than zero errors. Respect the owner's cleanup rules and avoid destructive cleanup without authority.

QA nudges recognise actual executable deployment commands, not filenames mentioned in readers or syntax checks. Such recognisers are advisory, not security parsers. A resume or repeated hook retains the active task and prior approvals.

If adopting untracked backups, test restore and content verification before calling them recoverable; define scheduling, remote retention and permitted deletion. Prefer committed planning in the core. Deployment and remote tracker operations require their own preflight and existing project authorisation; never infer them from installation consent.
