# Optional modules and evidence

The core ships Markdown or GitHub Issue planning and deterministic helpers. The optional hosted Projects adapter supplies a persistent portfolio; it does not require a local server. Browser recording, deployment and untracked backup scheduling remain separate modules. Selecting an unavailable module must produce an explicit unsupported result; no stub may count as installed or verified.

If adding a board, serve only its intended read-only files on loopback. Never serve the whole private state directory. Show missing/stale data honestly, label demo data, copy the selected host's command and verify that the chosen surface actually opens. Avoid speculative Mod APIs and unverified deep links.

Recorded QA is ticket-driven. Honour selected golden or composed input policy. Use the intended consented local browser/profile and existing target; do not bypass connection consent or switch to another user's browser. Require first-frame readiness and reject zero-frame recordings. Preserve raw wait time and label any acceleration; native capture and historical recordings cannot certify a fresh browser test. Incomplete diagnostics have unknown counts rather than zero errors. Respect the owner's cleanup rules and avoid destructive cleanup without authority.

QA nudges recognise actual executable deployment commands, not filenames mentioned in readers or syntax checks. Such recognisers are advisory, not security parsers. A resume or repeated hook retains the active task and prior approvals.

If adopting untracked backups, test restore and content verification before calling them recoverable; define scheduling, remote retention and permitted deletion. Prefer committed planning in the core. Deployment and remote tracker operations require their own preflight and existing project authorisation; never infer them from installation consent.

For a persistent board, use the source distribution's `extras/github/board.mjs`. `create --owner <login> --title <title> --authorization <scope>` creates a private Project and verifies its visibility. Save the returned URL as `tracker.project_url`. `sync --url <url> --repositories <JSON owner/repo list> --issues <JSON issue URL list> --authorization <scope>` adds only the selected existing Issues, verifies readback and never removes unrelated cards. `inspect --url <url>` reads the hosted inventory with pagination. GitHub CLI needs Projects access as well as access to the selected repositories. Request that access only when Projects is selected. One Project can span repositories; IDs always include owner/repository. Existing owner planning issues can be displayed without importing them as executable ticket contracts.

The hosted URL persists across ticket sessions, app exits and restarts. Pin or bookmark it once. GitHub's native board/table views and issue state are presentation; moving a card does not grant a claim or verify landing. New issues need explicit addition or an owner-selected GitHub Project auto-add workflow. The adapter never installs a polling service, opens extra repository access or publishes a private portfolio. Preserve existing Projects and inspect them before retrying a creation whose response was lost. API/authentication failures remain visible and never cause a replacement board or a cached authority fallback. The [GitHub Projects API guide](https://docs.github.com/en/issues/planning-and-tracking-with-projects/automating-your-project/using-the-api-to-manage-projects) documents the required separate add and field-update operations.

For opted-in automatic continuation, `scripts/waits.mjs` stores private, expiring records bound to the native session, ticket generation, owner nonce, approved contract and exact candidate. The source distribution's `extras/continuation/native.mjs` supplies `register`, `watch`, `inspect` and `stop`. Register with explicit `--repo`, `--ticket`, `--session`, `--host`, `--native-session`, `--condition` (JSON time or actual prerequisite), `--authorization`, `--task`, `--verification` (JSON executable/argument list), and `--expires` (within seven days), plus explicit `--native-options` permission choices. Native target readback is required before registration. Run `watch --repo <repo> --id <wait-id> --session <owner-id>` as the selected monitor; no service is silently installed. Its heartbeat and running process are evidence of monitoring, not just the presence of a wait file. The monitor must remain alive; a stopped Mac or process cannot deliver a wake. Durable records can be inspected and a registered monitor restarted explicitly.

Time waits use a known reset time; dependency waits name approved implementation/landing prerequisites and require verified local closeout, never a moved card. Do not invent a quota reset or claim an unknown blocker is scheduled. Explain the blocker and suggest an unblock step; offer other unblocked, disjoint work within existing authority. Cancellation prevents a future wake. Once delivery starts, stop the native turn through its host before cancellation. A crash or uncertain native response is `delivery-unverified` and requires inspecting the existing session before retrying. An acknowledgment or reminder is never successful continuation. The native adapter must resume the same persisted session, perform bounded authorized work, and turn its explicit acceptance check from failing to passing. Changed ownership, approval, candidate or package requires reconciliation and a new registration. Registration freezes the owner-selected continuation permissions; wake delivery cannot substitute new flags. For Claude select JSON tools/allowed_tools and permission_mode (manual, dontAsk or acceptEdits); for Codex select sandbox (read-only or workspace-write) and the explicitly reviewed project/hook trust config list, with optional `network_access: true` only when the bounded task needs network tools. Network access defaults to false and is never broadened on wake. No bypass mode is supported. Choose only permissions covered by the existing bounded authorization. The helper rechecks changed-file territory after native work. It never authorizes publishing or expands project scope.

Registration is idempotent for the same exact continuation and refuses conflicting active waits for one owning ticket/session. Inspect or cancel the old intent before superseding it; a recorded intent is not a running monitor. On an explicit owner stop/pause, cancel the corresponding wait through the helper; UI interruption alone is not a qualified withdrawal of a separate monitor. The adapter re-probes its native target before delivery, and completion already verified for the same contract cancels a redundant wake without starting a model turn.
